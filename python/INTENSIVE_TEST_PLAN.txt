================================================================================
           EAS 2.0 企业级高强度测试计划 - 最终版
================================================================================

【概述】

本高强度测试设计涵盖 10 个测试模块，包含 250+ 个测试用例，预计 3-5 小时
完成全部测试。该测试套件用于全面验证 EAS 2.0 系统的功能、性能、安全性
和可靠性。

================================================================================
【测试模块详细设计】
================================================================================

模块 1: 推断指令高强度矩阵 (50+ 用例, ~5 分钟)
─────────────────────────────────────────────────
功能: 验证所有工具在所有可能的 inputs 场景下推断指令的正确性

关键测试用例:
  [text_editor]
    ✓ 创建/追加 (content/code 字段)
    ✓ 替换 (old_text/search + replace)
    ✓ 插入 (line_number 字段)
    ✓ 读取 (仅 path)
    ✓ 空内容、空路径、编码参数
    ✓ 超长内容 (10KB+)
    ✓ 路径遍历 (../..)
    ✓ 特殊字符、多余字段等

  [command_runner]
    ✓ 简单命令 (echo, ls)
    ✓ 空命令、超长命令
    ✓ Python 命令、管道命令
    ✓ 超时参数 (5s, 0, -1)
    ✓ 工作目录参数
    ✓ Shell 参数 (True/False)
    ✓ 命令注入场景

  [web_fetcher]
    ✓ 简单 URL (http/https)
    ✓ 下载 (path/save_to/output 字段)
    ✓ 空 URL、无效 URL
    ✓ FTP 等其他协议
    ✓ 超长 URL、特殊字符 URL
    ✓ 内网 IP、本地端口
    ✓ 自定义头、POST 方法

验证点:
  ✓ 推断指令 100% 在工具声明中
  ✓ 工具能够正确处理推断指令

─────────────────────────────────────────────────────────────────────────────

模块 2: 边界条件高强度测试 (40+ 用例, ~10 分钟)
─────────────────────────────────────────────────
功能: 验证系统在极端情况下的行为

字符串边界:
  • 空字符串 ("")
  • 超长字符串 (10MB+)
  • 特殊字符 (\x00, \n, \r, \t, \x1a)
  • 国际字符 (中文、日文、emoji)
  • SQL 注入 (' OR '1'='1)
  • HTML/XML 特殊字符

数字边界:
  • 0、负数、极大/极小整数
  • 浮点精度问题
  • 超时值 (0, -1, 99999)

路径边界:
  • 空路径
  • 绝对/相对路径混合
  • 目录遍历 (../../etc/passwd)
  • Windows/Unix 路径混合
  • 不存在的路径、无权限路径

URL 边界:
  • 无效 URL、过长 URL
  • 非 http/https 协议
  • IP 地址 (公网、内网、本地)
  • 特殊字符编码

验证点:
  ✓ 无安全漏洞 (SQL 注入、路径遍历)
  ✓ 错误处理正确
  ✓ 没有系统崩溃

─────────────────────────────────────────────────────────────────────────────

模块 3: 并发执行高强度测试 (20+ 场景, ~15 分钟)
─────────────────────────────────────────────────
功能: 验证系统在并发场景下的正确性和安全性

并发步骤执行:
  • 5 个步骤并发执行
  • 10 个步骤并发执行
  • 50 个步骤并发执行
  → 检查竞态、死锁、数据一致性

并发计划执行:
  • 5 个不同计划同时执行
  • 验证计划隔离
  • 检查全局状态污染

并发 API 请求:
  • 10 个并发 execute 请求
  • 验证全局执行锁
  • 检查 400 错误返回

并发数据库操作:
  • 多个步骤同时写 steps 表
  • 验证事务一致性
  • 检查"database is locked"处理

竞态条件:
  • execute_step() vs get_plan() 竞争
  • 步骤完成前读取计划状态

验证点:
  ✓ 没有数据损坏
  ✓ 没有死锁
  ✓ 没有内存泄漏

大步骤计数:

验证点:
  ✓ 性能可接受
  ✓ 内存使用合理
  ✓ 数据库查询高效

模块 5: 长时间运行稳定性测试 (3 场景, ~1-2 小时)
─────────────────────────────────────────────
功能: 验证系统的长期稳定性

连续执行:
  • 100+ 顺序步骤执行
  • 每 10 步查询状态
  • 检查内存、文件描述符、数据库连接泄漏

持续压力:
  • 1 小时内最大吞吐量
  • 监控 CPU、内存、磁盘

重复场景:
  • 相同步骤执行 1000 次
  • 检查累积错误

监控指标:
  • 内存占用增长率 < 10%
  • 响应时间无显著衰减
  • 无内存泄漏

模块 6: 数据一致性高强度测试 (30+ 检查点, ~20 分钟)
────────────────────────────────────────────
功能: 验证多维度的数据一致性

状态转移验证:
  • 所有合法转移验证 (Pending→Running→Success/Failed)
  • 非法转移拒绝 (Success→Running)
  • 转移原子性保证

多源数据一致性:
  • steps 表 vs plans.segments JSON 一致
  • get_plan() 返回数据 vs DB 数据一致
  • 缓存 vs DB 一致

并发修改一致性:
  • 并发更新同一步骤
  • 最后写入胜利或错误

事务完整性:
  • 中途中断验证
  • 孤立数据检查

模块 7: 错误恢复高强度测试 (25+ 异常, ~15 分钟)
──────────────────────────────────────────
功能: 验证系统对各种错误的处理

工具执行异常:
  • 工具抛出异常
  • 工具返回错误状态
  • 工具超时
  • 工具返回无效输出

数据库异常:
  • 连接丢失
  • 锁定超时
  • 磁盘满
  • 权限不足

API 异常:
  • 无效 JSON
  • 缺失字段
  • 字段类型错误
  • 超大请求体

资源异常:
  • 内存不足
  • 磁盘空间不足
  • 文件描述符耗尽
  • 网络连接失败

恢复验证:
  • 异常后可继续工作
  • 数据一致性维护
  • 错误正确记录

  • 获取计划: < 20ms

吞吐量:
  • 每秒步骤数

  • 工具相对吞吐量

模块 10: 状态机完整性测试 (15+ 转移, ~5 分钟)
────────────────────────────────────────
功能: 验证状态转移逻辑

合法转移:
  • Pending → Running ✓
  • Running → Success ✓
  • Running → Failed ✓
  • Running → Running ✓

非法转移:
  • Success → Running ✗
  • Failed → Pending ✗
  • Success → Failed ✗

转移副作用:
  • 相关字段更新
  • 事件触发
  • 转移记录

  pytest test_*.py --benchmark-only

  pytest test_*.py --cov=executor --cov=tools
