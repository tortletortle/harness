# 新增 4 个工具实施计划（按 TOOL_INTERFACE_DESIGN.md 契约）

分两批：第一批低风险、零新依赖，先验证落地清单好用；第二批上对外能力。每个工具都走完整九步清单（实现→注册→副作用登记→instruction 推断→设计期接入（如进白名单）→测试→文档→冒烟）。

## 批次一：lint_gate 工具化 + github_operator

### 1. lint_gate 收编注册（改动最小）
现状：`python/tools/lint_gate.py` 的 `lint_python()` 是 file_creator/text_editor 内部用的**写入前语法门禁**（纯 `compile()`，只管 .py），不是独立 linter。方案：
- 在同模块加 `LintGateTool` 类（tool_id `lint_gate`，category `test`）：instruction `lint_file`，inputs `{path}`，走 `resolve_workspace_path`；返回 `success` + `detail` + `exit_code`（0/1，让验收器 `exit_code` 类型直接可用）。
- 注册进 `ToolRegistry._register_default_tools`；`_infer_instruction` 加 path→lint_file 分支。
- 进计划白名单（designer `__init__.py:674` 提示词）+ `json_fixer.TOOL_CONTRACTS` 加条目：`required_inputs=("path",)`，acceptance 用 `exit_code`。
- 测试：新 `tests/python/test_lint_gate_tool.py`（元数据四件套 + 好/坏文件两态 + 文件不存在 blocked + force 语义不泄露到工具层）。现有 `test_lint_gate.py` 不动。

### 2. github_operator（gh CLI 已装：v2.88.1，已认证 tortletortle，scopes 够用）
- 新文件 `python/tools/github_operator.py`，完全照 test_runner 模式：**服务端白名单 argv 模板**（`gh pr create/view/checks` 的固定骨架），argv 列表拼接无 shell；inputs `{action, title, body, base, head, number, branch}`，未知 action → `blocked`。
- instructions：`pr_create`（title/body 必填）、`pr_status`（number 或 branch，只读）。
- `capabilities.py`：`ToolCapabilityAdapter.spec` 新增外部副作用集合 `_EXTERNAL = {"github_operator"}` → `side_effect="external"`、`idempotent=False`（现集合词汇只有 none/reversible，扩一个值）。
- executor：把 `github_operator` 加入 cwd 注入集合（`executor/__init__.py:177-180`，让 gh 固定跑在 Grant 工作区）。
- **不进计划白名单**（pr_create 是对外副作用，计划不应自动建 PR）；对 coding_agent 的 `allowed_tools` 可用。
- 测试：`test_github_operator.py`（模板/拦截/元数据）+ `test_github_operator_security.py`（无 shell、注入串成单个 argv 项、模板外命令拒绝）；真实 gh 用例打标 `RUN_REAL_GH=1` 只跑只读 pr_status。

## 批次二：http_api + browser_check

### 3. http_api（httpx==0.26.0 已在 requirements，零新增依赖）
- 新文件 `python/tools/http_api.py`：一次调用一请求。instruction `send_request`，inputs `{url 必填, method, headers?, json?, params?, expected_status?, timeout}`；方法白名单 `{GET,HEAD,POST,PUT,PATCH,DELETE}`，白名单外 blocked。
- 复用 `web_fetcher._validate_url` 防 SSRF（私有 IP/内网地址拒绝，super_search 已有先例）；`url` 键天然进 Grant 的 `allowed_hosts` 检查。
- 响应体截断（沿用 20MB 上限 + 返回值尾部截断约定）；返回 `{success, status, json|text 截断, elapsed_ms}`；`success = status==expected_status（默认 2xx）`，同时返回 `exit_code` 0/1 供验收。
- side_effect="external"（POST/DELETE 可能）→ 不进计划白名单。
- 测试：`test_http_api.py`（本地 `ThreadingHTTPServer` 确定性 GET/POST/expected_status，零外网）+ `test_http_api_security.py`（SSRF 私有 IP 矩阵照抄 test_web_fetcher_security 模式、方法白名单、scheme 拒绝）。

### 4. browser_check（唯一新依赖：Playwright）
- 定位：**一次性无状态页面检查**，不做会话/多步操作（现有工具是静态无状态模型，会话浏览器留待演进项）。instruction `check_page`：inputs `{url 必填, expect_text[]?, not_expect_text?, expect_selector?, timeout, screenshot(→`output` 键存截图路径)}`；一次调用内完成 打开→断言→截图，返回逐项断言结果 + `exit_code`。
- `python/tools/browser_check.py`：**懒加载 playwright**，未安装 → `blocked`（"浏览器依赖未安装"），不炸注册表。requirements.txt 加 playwright，README/启动脚本注明需 `playwright install chromium` 一次。
- SSRF 同上复用 `_validate_url`；截图路径必须用 `output` 键（进 `_PATH_FIELDS`，Grant 才管得住）。
- **进计划白名单** + `TOOL_CONTRACTS`（`required_inputs=("url",)`, `require_acceptance=True`, `required_acceptance_types={"exit_code"}`）——它就是给验收步骤用的。
- 测试：`test_browser_check.py`（import guard：无 playwright 自动 skip；输入校验矩阵；SSRF）+ 打标 `RUN_REAL_BROWSER=1` 的真实用例（指向本地静态页 + 截图落盘断言）。
