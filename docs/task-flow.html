当前任务处理流程

从用户需求到设计、审批、执行、验收和恢复的完整路径。蓝色是主流程，紫色是授权与 Agent 能力，绿色是验收与交付，琥珀色是人工介入和恢复分支。

Python / FastAPI · SQLite · React · WebSocket
主任务阶段授权 / Agent / 工具验收 / 持久化审批 / 恢复

01用户提交需求

InputView → POST /api/design

请求先经过 API Token 鉴权和参数校验，再准备工作区、工具目录、Skills、知识注入和模型配置。

Bearer / X-API-Token项目上下文工具目录Skills / Knowledge

02Designer 生成设计书

python/designer/__init__.py

LLM 输出需求理解、架构、难度、所需工具、风险和验收建议；结果写入 SQLite，并可使用设计缓存。

设计缓存工具评估设计期搜索 Grant

03用户审批设计

DesignView → /api/design/{id}/approve

用户查看设计书后批准、拒绝或提交修改意见。反馈会回到 Designer，批准才会进入计划阶段。

批准拒绝 / 修订

04生成并校验执行计划

Designer → JSON 修复 → 契约校验 → SQLite

计划包含步骤、工具、输入、依赖、重试和验收条件。coding_agent、test_runner、test_passes 等特殊契约在设计期 fail-closed 校验。

plans / steps工具存在性Agent 契约Acceptance 契约

05用户启动执行

PlanView → POST /api/plan/{id}/execute → execute_plan_background()

系统创建 execution run，当前以顺序步骤执行为主，并为每一步记录状态和事件。

06步骤执行内部链路

python/api/server.py + python/executor/__init__.py
普通工具

file_creator、text_editor、command_runner、test_runner、lint_gate、git 等。

coding_agent

受权读文件 → 模型修改 → full/patch 写回 → 测试或验收反馈。

human_tool

人工步骤强制进入审批；批准后执行，拒绝或超时为 blocked 失败。

07结果分支与恢复

状态机 + checkpoint + step_events
Success → 下一步

验收通过，保存 outputs、evidence、usage 和审计记录。

Retry / Paused → 恢复

可重试错误有限重试；用户可暂停，之后从 checkpoint resume。

Failed / RolledBack

不可重试、审批拒绝或验收耗尽时终止；支持事件重放和回滚分支。

08实时交付与持久化

WebSocket /ws/logs + React 控制台

后端推送日志、plan_update、审批事件和版本号；前端丢弃过期事件并用轮询校准。最终状态和执行摘要落入 SQLite、审计日志与 PROJECT_MEMORY.md。
