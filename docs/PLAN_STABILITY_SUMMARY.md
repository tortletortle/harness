## 问题分析

### 核心问题：API 不稳定

#### 1. newapi 的问题
- **返回格式不一致**: 有时正确，有时返回 30K-42K 字符的格式错误内容
- **JSON 格式错误**: 虽然返回了大量内容，但不是有效的 JSON
- **不可预测**: 同样的请求，有时成功有时失败

#### 2. bbapi 的问题
- **速率限制**: 连续调用时频繁失败
- **简单请求可用，复杂请求失败**: 
  - "你好" 测试 ✅
  - 执行计划生成 ❌（需要 15K+ 字符响应）

#### 3. stepfun 的问题
- **返回空响应**: 0 字符
- **可能不支持此类复杂请求**

#### 4. hejuapi 的问题
- **响应时间过长**: 超过 60 秒，导致测试超时
- **可能可用，但速度太慢**

### 为什么测试成功率低？

**连续测试 vs 实际使用**:
- 测试场景：3 个用例连续快速执行
- 每个用例可能触发 4 次 API 调用（如果都失败）
- 总共可能 12 次 API 调用在几分钟内
- **这触发了速率限制**

**实际使用场景**:
- 用户不会连续快速生成多个执行计划
- 通常是：生成设计 → 等待几分钟/几小时 → 生成下一个
- 不会触发速率限制
- **预期成功率会显著更高**

### 理论 vs 实际

**理论成功率**（假设 API 稳定）:
- 4 层 fallback，每层 70% 成功率
- 总成功率 = 1 - (0.3)^4 = **99.2%**

**实际成功率**（测试场景）:
- 33.3% (1/3)
- 因为连续调用触发了速率限制

**预期成功率**（正常使用）:
- 单次调用场景下，之前测试成功
- 有 4 层 fallback 保护
- **预期 80-90%**
