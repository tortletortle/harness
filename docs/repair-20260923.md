## 2. 六项修复逐条对应

### H-01：Completed 后仍占用执行权

- 完成 Run、清理审批/授权、释放所属 reservation 后，才进行可选报告的网络 I/O。
- 报告按 Run 保存不可变计划快照，重跑计划不会让旧报告读取新计划状态。
- 报告任务持久化状态，生成幂等；旧任务回调仍受 token fencing 保护。
- 用量上下文改为 ContextVar，避免报告与下一计划相互覆盖 plan_id。
- 报告只读快照，用量写入主工作区，不重新创建已经合并/删除的执行 worktree。

**对比：** 原审计观察到约 68.219 秒的释放等待及后续 409；修复实测在报告仍进行时就能启动下一计划。

### H-02：限流不降级、设计错误被包装成 500

- 引入结构化 `LLMRequestError`，保留状态码、可重试性及 Retry-After，不把上游原文或密钥写入异常响应。
- 设计对话和最终报告遇到可恢复故障时，优先切换已配置的备用模型；最后路由最多重试一次。支持数值/HTTP-date 的 Retry-After，较长等待不提前重试。
- OpenAI-compatible 同 endpoint/key 在本进程默认最多 2 个并发请求；可用 `EAS_LLM_MAX_CONCURRENCY` 调整。不同进程或其他应用的额度不在此限制范围内。
- 设计/审批路由不再吞掉 GenerationError、HTTPException。耗尽后的上游限流返回 429，其他暂时性服务故障返回 503，权限/不可用及一般生成失败返回 502。

**证据边界：** 429 的重试、预算、Retry-After、取消传播和 HTTP 契约由故障注入单元测试验证；真实自动降级使用真实拒绝访问的主模型，观察到 **403 → 自动备用 Qwen → 成功**。本轮未捕获真实 429，不能称为“真实 429 恢复实测通过”。

### H-03：stepfun_chat 两条路由无权限

```yaml

    primary:
      provider: stepfun
      model: qwen3.8-max
```

这是合并到已有配置中的局部覆盖，**没有替换密钥，也没有给原 step-* 模型开通供应商权限**。模板与其他专用模型路由保留。该文件是 gitignored，本机已经修改；其他账号/机器必须独立验证权限，不能盲目套用。

### H-04：离线 pytest 使用真实凭据、启动外部 MCP

- 收集测试前屏蔽真实模型环境凭据及仓库 `.env` 自动加载；离线测试禁止读取仓库对应的真实账户密钥库。
- 默认拦截非 mock 的外部模型 HTTP 调用；真实测试需显式 `--live-models`。
- 生命周期子服务使用专用离线启动器：不加载本地模型覆盖、不注册真实 provider、不启动外部 MCP，不调用真实总结模型。
- 原未标记的真实 API E2E 归入 integration，默认不启动其模型子服务。
- 子服务使用内核分配的动态端口及独立就绪文件，避免并行 pytest 串连到另一套服务。

### H-05：Windows Rust 误选 linker / 找不到 Zig

- 构建脚本增加工具链预检，MSVC 路径拒绝 Git 的 `link.exe`。
- 自动选择可用 MSVC Developer 环境或 GNU + cargo-zigbuild，支持从当前 Python 的 ziglang 安装位置发现 Zig。
- PATH 只在脚本进程内临时调整，退出恢复；支持 `-Doctor`、`-Toolchain`、`-ZigPath`、`-Offline`。
- 已实测默认入口、42 个测试，以及 MSVC 缺环境时的明确拒绝提示；未声称在缺少 MSVC SDK 的本机完成了 MSVC 编译。

### H-06：关停请求无终态、Windows 管道清理异常

- lifespan 先等待执行/报告任务，超出宽限后取消并 gather，再关闭 MCP。
- 报告取消写入 interrupted；重启恢复原快照，报告任务总启动尝试数最多两次。
- MCP 初始化取消、发送失败、stdin EOF、进程树终止、读取任务取消与管道关闭均有清理路径；子进程被终止后等待回收。
- 真实关停恢复用例将宽限设为 0.05 秒以稳定覆盖取消分支；产品默认宽限仍为 15 秒。

**本轮真实日志中未再观察到** `I/O operation on closed pipe`、`_ProactorBasePipeTransport.__del__` 或 `Event loop is closed` 标记；这不等于证明所有 Windows 子进程异常都不可能发生。

保留的异常：

1. **固定文本探针拒答：** `glm-5.2` 返回 HTTP 200，但拒绝输出 `AUDIT_OK`。该项判为失败，未改写为通过。
2. **后续直接路由探针 502：** 同一主模型网关在普通算术探针中返回 502（约 81.343 秒）。该探针故意直测单条路由，不走业务降级，因此保留失败。Qwen 对照探针通过。
3. **原 Step 模型权限仍未开通：** 真实降级测试中故意使用被拒绝的 `step-3.5-flash`，获得 403 后由应用自动切换备用模型成功。正式聊天路由已避开该模型。

因此结论是：**应用回归和真实业务流程通过；上游服务可用性/回答遵从性仍有波动，不能保证永不出现 403、429、502 或拒答。**

报告任务样本共 11 个：10 个 completed，1 个 interrupted。后者是 B 验收结束时按默认宽限取消的可选报告，已明确持久化，非无记录的悬挂请求；同数据库重启恢复机制已由独立真实用例验证。
