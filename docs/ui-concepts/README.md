## 三个方向

| 方向 | 信息架构 | 适合场景 | 代价 |
|---|---|---|---|
| A Focus（推荐） | 精简导航 + 步骤主区 + 当前决策侧栏 + 轻量输出 | 日常创建、监督与审批 | 并行调试信息按需展开 |
| B Workbench | 活动栏 + 项目导航 + 步骤及输入参数 + 审阅栏 + 常驻输出 | 宽屏、高频调试 | 密度较高，窄窗要折叠 |
| C Timeline | 阶段概览 + 顺序事件 + 关联上下文 | 长任务排障、重试与审计 | 完整历史需要真实事件数据 |

推荐组合：A 作为默认体验，B 作为高级布局；C 先引入阶段/事件关联，不立即开发完整 DAG 编辑器。

- **GitHub Actions**：官方说明通过执行图和任务/步骤日志监控工作流。借鉴阶段与日志联动；简单顺序流程不必强行画 DAG。

- **Temporal**：官方说明 UI 支持查看执行、输入输出、事件历史与失败活动。借鉴状态证据链；不假定现有后端具备完整持久化事件模型。
  [2](https://docs.temporal.io/evaluate/understanding-temporal)

## 可体验的交互

- A/B/C 实际改变布局结构，不仅换色；主题可以独立切换以便比较。
- 点击步骤查看上下文，B 同时显示输入参数。
- 审批先展示范围，再弹出确认；只模拟批准一次，不运行脚本。拒绝保持阻塞。
- 执行 / 设计说明 / 产物标签支持左右方向键、Home、End。
- Ctrl/Cmd+K 命令面板，输入检索、上下选择、Enter 执行、Esc 关闭。
- 日志过滤、输出开合、密度切换、状态重置。
- “关于这份概念稿”列出未实现能力；项目列表和窗口按钮仅为静态结构示意。

## egui 落地映射

1. **视觉层**：在 `theme.rs` 收敛表面层级，减少逐行重阴影，统一状态色、选中态和字号。真实主体正文建议 13–14 logical px，辅助信息 11–12；本 HTML 是整体布局研究，不直接照搬所有 CSS 字号。
2. **布局层**：在 `app.rs` 调整现有 Panel 默认开合；步骤列表用轻分隔代替逐条大卡片。保留需求输入、设计审阅、执行控制的入口与语义。
3. **交互层**：审批队列必须仍可访问。决策侧栏不能只展示当前计划而丢掉其他计划的待批请求。复用逐请求 in-flight 状态，保留确认和 typing 守卫。
4. **数据层**：阶段耗时、重试/分支关系、事件与产物关联必须使用后端数据。现有环形日志不能替代持久化审计历史。
5. **暂不做**：依赖升级、自由 Dock、复杂流程编辑器、外部字体下载、网络/权限协议变更。

实施真实 GUI 后再执行 rustfmt、clippy、GUI 测试，在 Windows 原生窗口检查 DPI 125%/150%、中文字体和窄窗；HTML 测试不能替代这些检查。
