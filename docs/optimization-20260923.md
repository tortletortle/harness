## 1. 本轮新增发现与修复

以下 6 项均先在隔离测试中失败，再修复；不是声称生产环境已发生这 6 起事故。

| 问题 | 修复与验证 |
|---|---|
| 同一报告并发执行，重复调用摘要模型 | 同一 event loop、数据库路径和报告 job 共享一个独立 worker；重复调用方取消不会取消 owner。离线 40 并发仅调用一次摘要；真实 8 并发仅产生 1 次摘要调用、1 次 HTTP 请求。 |
| 报告已保存，但 WebSocket 通知失败会把状态降为 failed | 将通知与报告持久化分开；通知失败或通知阶段取消不再改写已完成状态。 |
| 取消时数据库写入失败，原始取消信号被替换 | 状态写入失败只记录告警，保留 `CancelledError`，并恢复上下文。测试注入数据库写入故障验证。 |
| 一条损坏的恢复记录阻断其他报告恢复 | 对恢复列表逐条校验 metadata、status、attempts、关联 Run；坏记录单独失败，不阻断后续有效记录。 |
| 启动中途失败时，已登记任务与 MCP 资源未清理 | 正常关停与启动失败共用清理流程：等待、取消并收集任务，再关闭 MCP。隔离测试在启动钩子注入已取得资源后抛错，验证资源释放。 |
| DEBUG 日志输出完整 API token | 删除明文 token 日志及无用局部变量；保留不含令牌内容的提示。用 AST 静态检查验证，不读取或打印真实 token。 |

## 4. 边界与仍需注意的事项

1. 并发去重仅适用于同一进程/event loop、同一数据库路径及 job；不是跨进程锁或分布式 exactly-once。
2. 数据库不可写时只能保留取消语义并告警，不能保证 interrupted 状态当场落盘；残留的 running 记录需待存储恢复后由重启流程处理。
3. 逐条恢复隔离以数据库能成功返回列表为前提；整库列表读取失败会告警并跳过恢复，不保证任意数据库损坏均可修复。
4. 哈希检查发生在报告 worker 被调用或恢复产物时；启动恢复跳过 completed 终态，不是定期扫描全部历史报告。
5. 有限宽限值不等于全局关停硬截止；不合作的任务或 MCP 清理仍可能拖延。
6. 已删除本次定位的明文 token 日志路径，但未删除历史日志；如旧日志曾共享，应轮换相关 token。
7. 未启动或重启生产后端，未执行 git commit/reset。验收在隔离工作区与数据库中进行。
