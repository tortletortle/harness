## 1. 新发现与修复

| 类别 | 旧行为与证据 | 修复 |
|---|---|---|
| 健康检查吞掉取消信号 | Anthropic、OpenAI、OpenAICompatible 三个 provider 的 `health_check` 用裸 `except` 捕获取消，返回 False；3 个用例复现。 | 改为只捕获普通 Exception，保留 CancelledError 等控制信号；普通调用失败仍返回 False。 |
| 并发配置缺少有效范围验证 | 空字符串/非法整数使初始化失败；0、负数和过大数值没有统一安全回退；5 个用例复现。 | `EAS_LLM_MAX_CONCURRENCY` 接受整数 1–64，非法值回退 2，告警不回显环境变量内容。 |
| HTTP 成功但响应畸形 | 200 + 空 choices 无法触发备用模型；错误类型的 content 导致 Pydantic 异常文本带出上游内容片段，且被标为不可重试；2 个用例复现。 | 将非 JSON、缺失字段、非法结构及响应模型校验失败归类为可重试的 LLMRequestError，保留真实 HTTP 状态，使用现有有限重试/备用模型机制。异常消息仅保留受控描述、异常类型和状态，不拼接任意上游/传输异常文本。 |

业务源码只修改 `python/llm_client/__init__.py`。调整了原测试中两项“要求透出原始异常文字”的断言，改为验证错误类型与不回显原始文本；新增测试明确覆盖响应和传输错误的隐私边界，而非仅删除失败断言。

现有空 content / tool-call 返回兼容行为保留，不把所有空文本都直接判作结构错误。未扩大现有重试次数或等待预算，未修改密钥和模型路由。

## 4. 范围与限制

- 共享限额作用于同一进程内相同 base URL/密钥组合，不是跨进程或跨供应商账号的全局配额。
- 已创建的限额不会随环境变量修改热更新；部署变更需重启进程。本轮未启动或重启生产后端。
- 畸形响应保留实际上游 `status_code=200`，同时 `retryable=True`；不能只用 HTTP 200 判断业务成功。现有 API 错误契约会按可重试性处理。
